# TRAINING MEDIA QA CHECKLIST

**Status:** بوابات جودة — لا تُعلَّم كمجتازة قبل وجود صور حقيقية وربط تطبيقي  
**Pilot:** 10 تمارين / 50 صورة مخططة  
**النتيجة الفعلية:** [`PILOT_QA_RESULTS.md`](./PILOT_QA_RESULTS.md) (حالياً `NOT_STARTED`)

كل بند يُطبَّق على كل صورة ما لم يُذكر أنه خاص بالتطبيق أو بالحزمة الخمس.

لا تُعتبر المواصفات الرياضية معتمدة قبل مراجعة Training & Exercise Manager.

---

## 1. مراجعة رياضية

- [ ] وضعية البداية صحيحة ومطابقة لـ `stage-a` المعتمد.
- [ ] مسار الحركة في `stage-b` و`stage-c` يطابق المرحلة المسماة (ليس نزولاً/دفعاً مفروضاً على تمارين السحب أو العزل).
- [ ] وضع المفاصل (كتف، مرفق، رسغ، ورك، ركبة، كاحل) مطابق للتعليمات المعتمدة.
- [ ] القبضة صحيحة ومتماثلة حيث ينطبق.
- [ ] وضع القدمين صحيح وثابت داخل الحزمة.
- [ ] المعدات تطابق `metadata.equipment` (`BARBELL` / `DUMBBELLS` / `NO_EQUIPMENT` / `PULL_UP_BAR` / `CABLE_STATION` حسب التمرين).
- [ ] مدى الحركة كامل أو مقصود بوضوح، وليس اختصاراً غير معلن.
- [ ] الخطأ المصور مفهوم من لقطة ثابتة واحدة.
- [ ] لا تُعرض وضعية قد تعرّض العميل للإصابة دون أن تكون موسومة في الواجهة كخطأ.
- [ ] الصورة تطابق تعليمات الأداء الصحيحة أو وصف الخطأ المعتمد — لا خلط بين الطبقتين.
- [ ] لا يُستخدم حدث لحظي غير قابل للتجميد (مثل ارتداد البار) كصورة خطأ.

**حارس:** `TRAINING_REVIEW_REQUIRED` حتى اعتماد 10/10.

---

## 2. مراجعة الاتساق البصري

تُراجع **الحزمة الخمس** لكل `external_id` كمجموعة:

- [ ] نفس المدرب في الصور الخمس.
- [ ] نفس الوجه والجسم (بدون تبديل نموذج).
- [ ] نفس الملابس.
- [ ] نفس المعدات (بار/دمبل/كيبل/عارضة مطابق).
- [ ] نفس الخلفية.
- [ ] نفس زاوية الكاميرا داخل الحزمة.
- [ ] عدم وجود أطراف إضافية أو مشوهة.
- [ ] عدم وجود أوزان أو مقابض غير متناظرة.
- [ ] عدم وجود نص أو شعار أو Watermark داخل الصورة.
- [ ] عدم وجود إطارات خضراء/حمراء أو علامات A/B/C مخبوزة.
- [ ] نسبة 4:3 واتجاه أفقي وفق العقد المقترح (بعد اعتماد المواصفات).

---

## 3. مراجعة الملفات

- [ ] اسم الملف صحيح (`stage-a` / `stage-b` / `stage-c` / `mistake-01` / `mistake-02`).
- [ ] `external_id` في المسار يطابق الكتالوج (`CH-001` وليس UUID أو slug).
- [ ] المقاس والنسبة صحيحان (المقترح: 1600×1200، 4:3 — `PROPOSED`).
- [ ] صيغة التسليم WebP والتطبيق؛ المصدر PNG في `assets/` فقط بعد الاعتماد.
- [ ] حجم الملف ضمن الحدود **المعتمدة** (الحدود الحالية في العقد `DRAFT` حتى مراجعة Performance).
- [ ] لا يوجد Duplicate لنفس `stage_code` داخل التمرين.
- [ ] لا يوجد Missing Asset من الخمسين بعد مرحلة التوليد.
- [ ] كل صورة مرتبطة بالمرحلة الصحيحة في Manifest.
- [ ] لم يُنسخ Placeholder الفيديو إلى مسار الصورة.

---

## 4. مراجعة التطبيق

تُنفَّذ بعد ربط Developer — ليست جزءاً من تجهيز العقود:

- [ ] تحميل الصورة المختارة فقط بالحجم الكبير.
- [ ] عمل محدد A/B/C مع مفاتيح `START_POSITION` / `PRIMARY_ACTION` / `END_OR_RETURN` المعروضة بأسماء التمرين.
- [ ] تغير التعليمات (`instruction_*`) مع المرحلة.
- [ ] عمل قسم الأخطاء (رمز + نص + صورة، لا لون وحده).
- [ ] Fallback عند فشل الصورة (لا واجهة فارغة).
- [ ] Lazy loading للصور غير الظاهرة.
- [ ] Responsive / `srcset` أو `OptimizedImage`.
- [ ] RTL للنصوص العربية.
- [ ] قارئ الشاشة: أزرار المراحل وalt text عربي/إنجليزي.
- [ ] عدم حدوث Layout Shift كبير (أبعاد ثابتة / هيكل مسبق).
- [ ] عدم منع بدء التمرين عند فشل صورة ثانوية.
- [ ] مسارات الفيديو الحالية في `exercise-media.ts` ما زالت تعمل دون انكسار.

مرجع الأداء: [`../../docs/v1/PERFORMANCE.md`](../../docs/v1/PERFORMANCE.md).

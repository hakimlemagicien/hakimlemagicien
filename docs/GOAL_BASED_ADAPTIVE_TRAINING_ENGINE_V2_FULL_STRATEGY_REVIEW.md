## 1. الخلاصة التنفيذية

الاستراتيجية التي وُضعت في المرحلة 1 نُفِّذت في المحرّكات بشكل متماسك:

الهدف → الملف العضلي → الأهلية → الوصف/المعايرة → تسجيل حقيقي → تضاعف التكرارات ثم الحمل → حجم فقط عند الدليل → استمرارية الحياة الواقعية → استجابة مناطقية → إشارة هدف → برنامج صالح أو حظر → شرح للعميل.

هذا المنطق **يعمل جيداً في الاختبار والمحاكاة**. مبادئ السلامة / الاستشفاء / البيانات الحقيقية / الالتزام قبل الحكم بالفشل **مثبّتة في الكود**.

لكن تفاعل العميل داخل `/app` اليوم **حلقة ناقصة**:

| يعيش مع العميل الآن | موجود كمحرّك فقط (اختبار/محاكاة) |
|---|---|
| وصف الجلسة + معايرة (Phase 4) | الحجم الأسبوعي / الاستشفاء / الديلود (Phase 7) |
| مشغّل التمرين + مؤقت جداري + أوفلاين (Phase 5) | الذكاء المناطقي/الهدف (Phase 9) |
| تقدّم التمرين بين الجلسات (Phase 6) | مولد البرنامج + المُصادِق (Phase 10) — لا يُستدعى من الأدمن/التطبيق |
| استمرارية اليوم الفعلي (Phase 8) | حفظ قرارات الهدف في `adaptive_decision_logs` ثم عرضها |
| بطاقات تقدّم على `/app/progress` (Phase 11) بدون تشغيل محرّك الهدف | إشعارات نظام التشغيل |

**لذلك:** الاستراتيجية صحيحة كعقل تدريبي. **لا تُغلق** كتجربة عميل مكتملة حتى تُوصل Phases 7 و 9 و 10 بمسارات التشغيل الحقيقية (بدون بناء محرّكات موازية).

## 4. هل الاستراتيجية المذكورة تعمل بشكل جيد؟

### 4.1 ما يعمل بشكل جيد (منطق + اختبار)

- **معايرة بدل كجم ثابت** لمستخدم V2 بلا تاريخ.
- **تكرار أولاً ثم حمل** (8/8/8 → 12/12/12 → زيادة حمل صغيرة).
- **فشل الحمل الجديد → إنقاص** وليس إجبار الحمل.
- **لا +10%** على المسار المدفوع.
- **لا حرق موضعي** (الخصر الراكد ≠ مزيد من البطن).
- **خسارة الدهون** لا تفرض HIIT / تكرارات عالية / راحة قصيرة؛ الركود الجسدي → مراجعة تغذية.
- **الأرداف البطيئة / الرباعية السريعة → إعادة توزيع** لا زيادة حجم الجزء السفلي كله.
- **السلامة والاستشفاء والالتزام** يغلبون «أضف عملاً».
- **البيانات الناقصة = ثقة منخفضة** لا تخمين واثق.
- **البرنامج الباطل لا يُفعَّل.**
- **التاريخ لا يُختلق** عند الهجرة.

محاكاة 8 أسابيع (Phase 12):  
`INCREASE_REPS ×3 → INCREASE_LOAD → KEEP_LOAD → …` مع حجم لا يتصاعد أسبوعياً تلقائياً.

24 سيناريو هدف × 2–5 أيام: صالحة أو بتحذيرات، بدون kg مخبوز.

### 4.2 أين تنكسر حلقة العميل

1. **مولد البرنامج غير موصول بالتعيين.** العميل المدفوع ما زال يعيش لقطة الكوتش/القالب. الاستراتيجية تُولَّد في الاختبار لا في «استلم برنامجك».
2. **محرّك الحجم لا يغيّر البرنامج الحي.** قرار KEEP/ADD/DELOAD يبقى في الدومين.
3. **محرّك الهدف لا يكتب ولا يُعرض كحالة هدف حقيقية.** `/app/progress` غالباً `INSUFFICIENT_DATA` حتى مع تاريخ تمرين، لأن الخطاف لا يستدعي `evaluateGoalResponse`.
4. **مساران:** معاينة مجانية ما زالت +10% وkg من الكتالوج. هذا متعمّد ومعزول، لكنه يعني أن غير المشترك لا يعيش استراتيجية V2.
5. **لا دفع نظامي.** التذكير داخل التطبيق فقط.

هذه ليست فشلاً في قواعد التدريب. هي **فجوة توصيل المنتج**.

## 5. رحلة العميل مقابل الاستراتيجية

| خطوة الاستراتيجية | في التطبيق اليوم |
|---|---|
| اختيار الهدف | الكويز / `goalId` — الربط الكانوني موجود |
| ملف الهدف | في المحرّك؛ لا يُ visibilize كملف للعميل |
| توليد برنامج | **غير مستدعى** — لقطة معيَّنة |
| وصف أول تمرين | **نعم** على المسار المدفوع (معايرة) |
| تسجيل سِت + جهد + راحة | **نعم** |
| الجلسة التالية تتقدّم | **نعم** (Phase 6 في المشغّل) |
| تفويت حصة | **نعم** استمرارية اليوم الفعلي |
| حجم أسبوعي يتكيّف | **لا** في التشغيل |
| استجابة مناطقية/هدف | **لا** في التشغيل |
| إعادة توليد برنامج | **لا** تلقائياً (صحيح) و**لا** عبر مسار كوتش لمرشّح Phase 10 |
| شاشة التقدّم تشرح | جزئي: استمرارية + اتجاهات تمرين؛ حالة الهدف غالباً ناقصة بيانات |
| الكوتش يرى الأثر | أعلام مراجعة؛ ليس متصفح قرارات كاملاً |

## 6. تفاعل المحرّكات معاً

الترتيب المعتمد سليم ولم يُكسر:

```
السلامة > الاستشفاء > الالتزام/البيانات > الاستجابة المناطقية > تحسين الهدف > توليد برنامج صالح
```

لا يوجد محرّك موازٍ خفي. مسار `legacy_free` معزول بـ `runtimeMode`.

الخلل الوحيد ذو الأثر على «إغلاق الاستراتيجية للعميل»:  
**7 و 9 و 10 لم تُحقَن في خط التشغيل الأسبوعي** (وظيفة حفظ قرارات + مسار تعيين مرشّح صالح).

## 7. ما الذي يمكن إغلاقه الآن

**يُغلق كعقد تدريبي (لا مرحلة 13):**

- الأهداف الستة وقواعدها المحظورة
- المعايرة / التقدّم المزدوج / عدم +10% على V2
- الحدود: لا حرق موضعي، لا سعرات من التدريب، لا ادعاء طبي للقوام
- هوية التمرين `external_id`
- اللقطة المعيَّنة كمصدر حقيقة للعميل المدفوع حتى يُفعَّل مولّد مصادق

**لا يُغلق:**

- «العميل يعيش النظام التكيّفي كاملاً في التطبيق»
- الإطلاق العام (ما زال `CONTROLLED_RELEASE` + موافقة CEO)
- عقد التغذية المشترك

## 8. العمل المتبقي قبل إغلاق تجربة العميل (توصيل فقط — ليست محرّكات جديدة)

1. مسار كوتش/داخلي: `generateTrainingProgram` → `validate` → `admin_assign` عند READY فقط.
2. وظيفة دورية محدودة: تشغيل Phase 7 و 9 على تاريخ محدود وكتابة `adaptive_decision_logs`.
3. `useTrainingProgressSummary` يقرأ القرارات المحفوظة (لا يعيد حساب المحرّك في الواجهة).
4. تنفيذ خطة RLS على Staging.
5. dry-run هجرات على نسخة غير إنتاجية.
6. cohort أجهزة حقيقية للتمرين.

بدون ذلك، إغلاق الاستراتيجية يعني إغلاق **العقل** لا **المنتج**.

## 9. الأدلة التنفيذية لهذه المراجعة

- قراءة تقارير Phases 3–12 + عقود Phase 2 + لوحة فجوات Phase 1
- بحث استدعاءات المحرّكات في `src/` (إنتاج مقابل اختبار)
- تأكيد المشغّل يستدعي `getNextSessionProgression` + `getCoreExercisePrescription`
- تأكيد `useProgramContinuity` على `/app/program`
- تأكيد `getWeeklyVolumeDecision` / `evaluateGoalResponse` / `generateTrainingProgram` **غير مستدعاة** من hooks أو admin UI
- تأكيد `useTrainingProgressSummary` لا يمرّر `goalDecision`
- نتائج Phase 12: `npm test` و `npm run build` ناجحان سابقاً (لا إعادة نشر)
